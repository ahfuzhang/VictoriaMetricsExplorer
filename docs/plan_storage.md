# 目标

实现每个用户的个性化存储。

# 细节

当用户点击第四栏右上角的 favorite 按钮时，会触发用户的个性化保存能力。

使用 Grafana User Storage API 来实现。

这个个性化保存的功能，主要是由前端 React.js 调用 Grafana 提供的 user storage API。与 APP 的 golang 后端无关。
当调用 user API 的时候，Key 有两类。
第一类的 key 是保存一个 tree 格式的 menu。
第二类的 Key 是由一个唯一的 tree node 的 ID 来指向菜单所对应的内容。

需要定义两个结构，一个叫 tree，一个叫 treenode。
Tree 里面定义了一个 current tree node ID。 每次在菜单树里面新增一个节点时，需要把当前这个值加 1 得到一个新的值，同时，加 1 后的值也要写回到用户存储里面去。
Tree 的这个结构里面存在一个叫 children 的成员，children 里面又包含了很多个 tree node 成员。因此，这样一个递归的结构实现了一个树形的结构。


存储到 user storage API 里面的数据都是用 proto 来定义的。
保存的时候：
1. 先把数据序列化成 Protocol Buffer 的二进制数据；
2. 再使用 gzip 压缩；
3. 再进行 Base64 的格式转换。

读出的时候与这个过程相反：
1. 先进行 Base64 的 decode；
2. 再进行 gzip 解压缩；
3. 再进行 protobuf 反序列化。

## 菜单树的显示

当用户打开 APP 时，在整个页面的第一栏，可折叠的菜单部分，最后一项就是用户自定义的菜单。

## 点击保存

在页面的第四栏右上角有一个 favorite 按钮，当用户点击 favorite 时，会出现一个保存界面。
保存界面分成两部分，第一部分是一个 treeview 的管理。用户可以在树节点上创建一个文件夹，或者创建一个节点。文件夹不能保存东西，只能用于视频的分组。节点，用于保存多个 promql 的查询表达式。
当用户选择了保存的节点时，继续第二部分对 PromQL 的配置。

PromQL 的配置包含以下几部分：
第一部分：PromQL 的表达式。提供一个多行文本框，用户可以手动去修改 PromQL 的表达式。
第二部分：PromQL 对应的名字。提供一个比较容易读的名字，来说明这个表达式是做什么的。
第三部分：PromQL 执行完以后的单位。典型的单位包括字节数、延迟、百分比。

当用户设置好要保存的树节点的位置还有 PromQL 的配置以后，就可以点击保存按钮。点击保存按钮以后，会把以上的数据放到 proto 文件所对应的 class 的成员里面，然后进行以下步骤：
1. 进行 protocol buffer 的序列化；
2. 进行 gzip 压缩；
3. 转成 base64 的格式；
4. 调用 user storage API 保存在 Grafana 的服务器上。

如果用户在保存的过程中修改了树的结构，还需要再做两件事情。
第一件事是需要先得到一个新的 Trino 的 ID，Trino 的 ID 是保存在 menu 这个菜单项的一个成员里面的。
第 2 件事情是，当有新的节点时：
1. 把新的节点加到 tree load 的对应位置；
2. 更新 max tree load ID 的最大值；
3. 调用 user storage API，把它保存在 Grafana 服务器。

## 菜单树的管理

在整个页面的第一栏里面，可折叠菜单的最下面一个就是用户自定义的菜单。在用户自定义菜单头部的右边有一个 settings 按钮，当用户点击这个按钮后，会弹出一个界面，在这个界面里面可以实现对菜单的。
这里需要支持菜单数的新增文件夹、删除文件夹。需要支持删除菜单节点。需要支持对节点修改名字。文件夹可以拖动，这样的话就可以调整文件夹的顺序和层级。
文件夹里面的节点也支持拖动。
所以菜单树的管理分为以下几种：
1. 新增文件夹
2. 删除文件夹
3. 修改文件夹的名字
4. 修改文件节点的名字
5. 可以拖动文件夹，修改文件夹的位置
6. 可以拖动文件节点，修改文件节点的位置。
7. 可以删除文件节点。
8. 可以删除文件夹，但是只有空的文件夹才允许删除。如果里面有文件内容的话，是不允许的。

请注意，上面提到的文件夹和文件是一种比喻，是指像文件系统的数据结构一样来管理分组，以及分组里面的具体 Key。
