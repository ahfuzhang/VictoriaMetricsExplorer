# 已知指标图表配置规划

日期：2026-11-02

依据：[prompt_20261101_config.md](prompt_20261101_config.md)。本计划已实现，实际配置说明见 [metric_config.md](metric_config.md)。根据后续要求，入口调整为 By Pod 第二栏顶部的 Important Metrics 链接，点击后展示配置图表；格式扩展支持 MetricsQL、stat、piechart、瞬时查询和 Grafana 原生 options / fieldConfig，以完整迁移 .NET dashboard。以下保留原始规划与简写示例。

## 1. 目标与现有配置的关系

- 每个 YAML 文件对应一个大类别，例如进程、Go Runtime、HTTP、VictoriaMetrics。
- 每个文件包含多个图表配置项，一个配置项对应一张图，可以包含多条查询。
- 后端在进程启动时一次性加载配置到内存。用户选择 By Pod 下的某个 Pod 分组后，在页面顶部展示当前范围内命中的已知指标图表。
- 图表配置描述指标名称、查询表达式、单位、说明和展示样式，首版覆盖曲线图、堆积曲线图和双坐标曲线图。

现有 `provisioning/plugins/app.yaml` 通过 `jsonData` 配置标签映射、缓存、超时和数据源白名单，解析入口为 `pkg/app/settings.go`。这些运行参数继续由原入口管理。新的 YAML 目录只存放图表定义；数据源地址和认证继续使用 Grafana 的数据源配置。

## 2. 环境变量名称

首版只新增一个环境变量，沿用仓库中已有的 `VMX_` 前缀：

| 名称 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `VMX_METRIC_CONFIG_DIR` | 目录的绝对路径 | 空字符串 | 插件后端读取已知指标图表配置的目录；未设置或为空时不启用此功能 |

约定：

1. 变量传给运行插件后端的 Grafana 容器，值使用**容器内路径**。
2. 只接收一个目录，不接受文件路径、逗号分隔的多个目录或 glob 表达式。
3. 只扫描目录第一层的 `.yaml` 和 `.yml` 文件，按文件名排序读取，不递归扫描子目录。
4. 允许读取挂载产生的文件符号链接，以兼容 Kubernetes ConfigMap；读取失败按配置错误处理。
5. 目录存在但没有配置文件时，加载空目录并记录提示；显式设置的路径不存在、不是目录或不可读时，启动报错。
6. 配置只在插件后端进程启动时读取。更新文件后重启插件后端或 Grafana 容器生效，首版不增加热加载开关、轮询间隔或管理接口。

Docker Compose 配置片段，合并到现有 `grafana` 服务中：

```yaml
services:
  grafana:
    environment:
      - VMX_METRIC_CONFIG_DIR=/etc/vmx/metrics
      - GF_PLUGINS_FORWARD_HOST_ENV_VARS=ahfuzhang-victoriametricsexplorer-app
    volumes:
      - ./config/metrics:/etc/vmx/metrics:ro
```

建议的宿主机文件布局：

```text
config/metrics/
  process.yaml
  go-runtime.yaml
  http.yaml
  victoriametrics.yaml
```

部署时需创建宿主机目录，并确保 Grafana 运行用户有权限读取。`config/metrics` 是新规划的图表目录，不放入 Grafana 的 provisioning 目录，避免被当作 Grafana 自身配置解析。

## 3. YAML 格式

### 3.1 文件层级

采用 UTF-8 YAML，每个文件只允许一个 YAML 文档，字段统一使用 `camelCase`，与现有 `jsonData` 风格一致。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `apiVersion` | 是 | 整数，首版固定为 `1`；用于后续格式升级 |
| `category.id` | 是 | 类别标识，全目录唯一，例如 `process` |
| `category.title` | 是 | 展示名称，例如“进程指标” |
| `category.description` | 否 | 类别说明，默认空字符串 |
| `category.order` | 否 | 整数，默认 `100`，越小越靠前 |
| `charts` | 是 | 非空图表列表 |

类别与图表 ID 使用小写字母开头，后续只允许小写字母、数字和连字符。图表的全局标识为 `<category.id>/<chart.id>`，例如 `process/cpu-usage`。类别 ID 不依赖文件名，改名文件不会改变图表标识。

### 3.2 图表字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 在所属类别内唯一的图表标识 |
| `title` | 是 | 图表标题 |
| `description` | 是 | 指标含义、聚合方式和单位口径说明 |
| `enabled` | 否 | 布尔值，默认 `true` |
| `order` | 否 | 整数，默认 `100`，越小越靠前 |
| `match.modes` | 否 | 默认 `[byPod]`，首版只接受 `byPod` |
| `match.metricNames` | 是 | 图表依赖的精确指标名列表，全部存在时才展示 |
| `rateWindow` | 否 | `rate` 等函数使用的窗口，默认 `1m`；必须为正整数加 `s`、`m` 或 `h` |
| `queries` | 是 | 非空查询列表，支持一张图多条查询 |
| `visualization.type` | 是 | `line`、`stacked`、`dual_axis` 三选一 |
| `visualization.axes` | 是 | 坐标轴定义，至少包含 `left` |
| `summary` | 否 | 在曲线旁显示一条查询的最近有效值；省略则只显示曲线 |

匹配及排序规则：

- 从当前数据源、时间范围和 Pod 分组对应的指标集合中进行匹配，复用 `metric-index` 的发现和缓存能力，不使用整个数据源的全局指标集合代替。
- 首版只支持精确指标名与“全部存在”的匹配，不引入指标正则和优先级覆盖。后续需要多种指标适配时，可以配置不同图表项。
- 同一个指标可以用于多张图。例如 CPU 指标既可以显示独立曲线，也可以参与 CPU 与内存的双坐标图。
- 类别按 `(order, id)` 排序，类别内图表按 `(order, id)` 排序；不依赖文件系统读取顺序。
- 指标发现结果被截断时，未发现的指标属于“尚未确认”，不能据此报告配置错误。命中的图表正常展示，发现不完整应提供提示。
- 图表查询返回空数据时展示“暂无数据”，不把空数据转换为零值。

### 3.3 查询、单位和图形字段

每个 `queries` 元素：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `refId` | 是 | 图表内唯一，使用大写字母开头的字母数字标识，例如 `A`、`B` |
| `expr` | 是 | 查询表达式模板，建议使用 YAML 的 `\|` 多行字符串书写 |
| `legend` | 否 | 固定图例名称；省略时使用结果标签，多序列时保留标签以区分曲线 |
| `axis` | 否 | `left` 或 `right`，默认 `left` |

每个坐标轴支持以下字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `unitId` | 是 | 单位 ID，首版支持 `none`、`percent`、`bytes`、`s`、`Bps` 及非空的 `suffix:<文本>` |
| `label` | 否 | 坐标轴标题，默认空字符串 |
| `min` / `max` | 否 | 有限数值；省略表示自动范围，同时指定时必须满足 `min < max` |
| `decimals` | 否 | 整数，范围 `0..10`；省略表示自动决定 |

使用 `unitId` 对接现有 `src/explorer/favorites/units.ts` 的显示逻辑；新配置不复用 `ChartPlan.unit` 的展示文本语义。例如配置百分比使用 `percent`，不是 `%`。同一坐标轴上的查询必须具有相同单位口径，转换需要明确写入表达式。

| 图形类型 | 约束 |
| --- | --- |
| `line` | 使用左轴，各序列独立绘制 |
| `stacked` | 使用左轴，将各序列按原始值堆积为面积曲线；不是百分比堆积 |
| `dual_axis` | 必须同时定义左右轴，且两侧各有至少一条查询；不进行堆积 |

`summary` 包含 `queryRef` 和 `reducer`：前者引用本图的 `refId`，后者首版只接受 `lastNotNull`。被引用查询应聚合为单条序列；如实际返回多条序列，则提示配置口径不符，不任意挑选或隐式求和。摘要使用对应坐标轴的单位，表示当前时间范围内最近的有限采样值，不代表额外发起了一次实时查询。

### 3.4 表达式模板

Pod 分组、标签筛选以及标签名称由后端生成，配置文件不写死某个 Pod 前缀。首版使用有限的占位符，不执行通用模板代码，也不替换任意环境变量：

| 占位符 | 替换内容 |
| --- | --- |
| `{{selector:指标名}}` | 含指标名称、当前 Pod 分组和当前标签筛选的完整 selector，例如 `{__name__="process_cpu_seconds_total",pod=~"vminsert-vmcluster-realtime-.*"}` |
| `{{rateWindow}}` | 当前图表配置的 `rateWindow`，默认 `1m` |
| `{{label:pod}}` | 当前组织配置中的 `podLabel`，默认 `pod` |
| `{{label:namespace}}` | 当前组织配置中的 `namespaceLabel`，默认 `namespace` |
| `{{label:cluster}}` | 当前组织配置中的 `clusterLabel`，默认 `cluster` |
| `{{label:node}}` | 当前组织配置中的 `nodeLabel`，默认 `node` |

约束：

1. `selector` 中的指标名必须出现在 `match.metricNames` 中；该列表应恰好覆盖所有查询引用的指标。
2. 所有指标选择器都通过 `selector` 占位符生成。禁止在模板内另外书写绕过当前范围的裸指标或选择器；实现时解析替换后的表达式并检查选择器结构，不能只用字符串替换判断。
3. 选择器复用 `pkg/resource/promql.go` 的标签校验、字符串转义和正则转义能力。Pod 分组限制与用户筛选取交集，不能互相覆盖。
4. 标签映射来自当前组织的 `Settings`，不在进程级图表目录里固定；占位符只能用于对应的表达式语法位置。
5. 首版模板使用 PromQL 公共语法，以适配现有两种数据源。MetricsQL 专用表达式及数据源类型选择字段留待后续扩展。
6. 启动时校验模板及替换样例后的表达式语法，运行时根据实际范围生成查询。未知或位置不合法的占位符直接报错。
7. `rateWindow` 与绘图 `step` 是两个参数。配置作者需选择适合采集间隔的窗口；`1m` 是默认示例值，较慢采集可配置为 `5m` 等。

## 4. 完整配置示例

下面可作为后续 `config/metrics/process.yaml` 的内容，展示同一类别下的三种图形样式：

```yaml
apiVersion: 1

category:
  id: process
  title: 进程指标
  description: 当前 Pod 分组内的进程 CPU 与内存概览
  order: 10

charts:
  - id: cpu-usage
    title: CPU 使用率
    description: 以单核为 100%，汇总当前 Pod 分组内所有匹配进程；多核或多进程合计可超过 100%。
    enabled: true
    order: 10
    match:
      modes: [byPod]
      metricNames: [process_cpu_seconds_total]
    rateWindow: 1m
    queries:
      - refId: A
        expr: |
          100 * sum(rate({{selector:process_cpu_seconds_total}}[{{rateWindow}}]))
        legend: CPU 使用率
        axis: left
    visualization:
      type: line
      axes:
        left:
          unitId: percent
          label: CPU（单核 = 100%）
          min: 0
          decimals: 2
    summary:
      queryRef: A
      reducer: lastNotNull

  - id: memory-by-pod
    title: 各 Pod 进程驻留内存
    description: 按集群、命名空间和 Pod 汇总进程驻留内存并堆积；不等同于容器内存限制使用率。
    order: 20
    match:
      metricNames: [process_resident_memory_bytes]
    queries:
      - refId: A
        expr: |
          sum by ({{label:cluster}}, {{label:namespace}}, {{label:pod}}) (
            {{selector:process_resident_memory_bytes}}
          )
        axis: left
    visualization:
      type: stacked
      axes:
        left:
          unitId: bytes
          label: 驻留内存
          min: 0

  - id: cpu-and-memory
    title: CPU 与内存
    description: 左轴为单核基准 CPU 百分比，右轴为进程驻留内存总量。
    order: 30
    match:
      metricNames:
        - process_cpu_seconds_total
        - process_resident_memory_bytes
    rateWindow: 1m
    queries:
      - refId: A
        expr: |
          100 * sum(rate({{selector:process_cpu_seconds_total}}[{{rateWindow}}]))
        legend: CPU 使用率
        axis: left
      - refId: B
        expr: |
          sum({{selector:process_resident_memory_bytes}})
        legend: 驻留内存
        axis: right
    visualization:
      type: dual_axis
      axes:
        left:
          unitId: percent
          label: CPU（单核 = 100%）
          min: 0
          decimals: 2
        right:
          unitId: bytes
          label: 驻留内存
          min: 0
```

CPU 单位口径：原需求中的 `sum(rate(process_cpu_seconds_total[1m]))` 表示每秒消耗的 CPU 秒数，可理解为使用的 CPU 核数。上述配置显式乘以 `100` 后按 `percent` 显示：查询值 `25` 显示为 `25%`，`250` 显示为 `250%`，不再由前端重复乘以 `100`。如果要展示“占 Pod CPU limit 的百分比”，需要额外配置 CPU limit 指标及除法表达式，不能只修改单位名称。

## 5. 加载、校验与实现衔接

### 5.1 加载与错误处理

1. 在 `main.go` / `pkg/app.Manage` 启动路径中读取环境变量并加载目录，在启动服务前完成。Grafana 为各组织创建 `NewApp` 时共享只读图表定义，组织标签和数据源信息在请求时绑定。
2. 每个文件依次完成严格 YAML 解码、字段校验、模板语法校验，再建立按指标名检索的内存索引。
3. 拒绝重复 YAML key、未知字段、不支持的版本、重复类别 ID、同类别重复图表 ID、重复 `refId`、非法单位和不匹配的坐标轴引用。`enabled: false` 的配置项仍需通过校验。
4. 任一文件错误时，本次加载整体失败并返回启动错误，不发布只加载了一部分的目录。错误应包含文件名、图表 ID、字段路径和可获得的行号。
5. 全部成功后一次性发布只读目录，并记录文件数、类别数、图表数和启用图表数。此目录是进程内配置快照，不使用查询缓存的 TTL。

### 5.2 与当前代码的衔接

- 新增独立的配置加载模块，例如 `pkg/metricconfig`，集中维护结构定义、默认值、校验、模板编译和索引。
- `pkg/app/app.go` 与 registry 向资源处理层传递只读目录；图表查询仍走当前组织的数据源白名单和 Grafana 代理链路。
- 为已知图表增加独立的规划响应，包含图表 ID、多条查询、左右轴和摘要定义。现有 `proto/explorer/explorer.proto` 的 `ChartPlan` 只有单条 `query` 与单个 `unit`，不能直接表达完整的新格式。
- 在 `src/explorer/components/Explorer.tsx` 的 By Pod 视图顶部增加图表区域。选中 Pod 分组即触发匹配，不要求先点击某个 metric；切换数据源、范围或筛选时取消旧请求并重新生成查询。
- 复用现有 `query-range`、单位格式化和图表组件；堆积、双坐标及多查询组合按新配置补齐。复用现有请求并发限制，优先加载可见图表，避免图表目录增长后同时查询全部图表。

### 5.3 后续实现验收项

- 环境变量未设置时保持现有页面行为；正确挂载多个 YAML 文件时能一次性加载全部类别。
- 用上面的示例验证曲线、堆积、双坐标、单位和 CPU 最近值展示；指标缺失时只展示依赖满足的图表。
- 验证自定义 `podLabel`、多组织、不同数据源以及带特殊字符的 Pod 分组和标签值，确保查询范围正确。
- 验证未知字段、重复 ID、错误单位和模板均产生明确错误；修改文件后重启可加载新配置。
- 验证空数据、单图查询失败、快速切换范围以及指标列表截断，不把错误或旧结果展示为当前正常数据。
