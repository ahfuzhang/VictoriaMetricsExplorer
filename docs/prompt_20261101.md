我希望在 metric-index 接口中做调整：

1 先访问 cache 来拿到数据；cache 没有再访问后端

   cache 的 key 中，一部分是 metrics 的前缀。

   所以 cache 有三种：按 metric name 前缀的，按照 pod 的前缀的，按照 node 名字的。

   注意 cache 的过期时间的处理  =&gt; 进一步地，在 app.yaml 中增加 cache 过期时间的配置。默认为 30 分钟过期。

2 metric-index 中返回的数据，增加一个 bit_flags 字段，里面存在 64 个 bool 值。

   bit 0: 是否已经查询了 0 值

  bit 1: 是否为 0 值。

   以上两个值，说明了后续的 metric-types 接口是否需要查询 0 值。

3 metric-index 中返回的数据(也包含 cache 的数据结构)，增加 metrics type 的字段，默认为 unknown

    通过后缀判断出来的类型除外

4 metric-types 接口调用的时候，仅仅对 没有 metric type 和没有是否 0 值的 metrics 发起查询。

   查询得到结果后，更新缓存。

   等下下次调用 metric-index 接口的时候，所有需要的数据都在缓存中，从而减少一次对 metric-types 接口的调用。
